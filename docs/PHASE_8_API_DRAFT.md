# Phase 8 API Draft

Date: 2026-05-29

## Scope

This is a planning document only. No FastAPI app, routes, frontend, downloader, transcription module, media download, Whisper run, MVP, extension, or desktop wrapper is implemented in Phase 8.

The future API should expose a local-only interface for the browser UI and should bind only to `127.0.0.1`.

## `GET /health`

Purpose: allow the UI to confirm that the local backend is alive.

Request shape:

```json
{}
```

Response model:

```json
{
  "status": "ok",
  "app": "universal-media-extractor",
  "version": "0.1.0",
  "local_only": true
}
```

Errors:

- normally none;
- process unavailable means the UI cannot connect.

Backend behavior:

- return static process health;
- optionally include dependency availability later.

Not current-stage behavior:

- no route is created in Phase 8.

## `POST /analyze`

Purpose: analyze a URL or, later, a local file and return normalized source details.

Initial request shape:

```json
{
  "source_type": "url",
  "url": "https://example.com/video",
  "user_confirmed_rights": false
}
```

Future local-file request shape:

```json
{
  "source_type": "local_file",
  "local_path": "/path/to/user-selected-file",
  "user_confirmed_rights": false
}
```

Response model:

```json
{
  "job": {
    "job_id": "analysis-...",
    "task_type": "analyze_url",
    "status": "succeeded"
  },
  "result": "AnalyzeResult"
}
```

Errors:

- unsupported source;
- timeout;
- network error;
- login required;
- cookies required;
- extractor failed;
- invalid analyzer output;
- missing `yt-dlp`.

Backend behavior:

- create a minimal analysis job;
- call `AnalyzeService.analyze_url(...)`;
- return `AnalyzeResult`;
- preserve analyzer errors in the response instead of throwing away partial state;
- save raw JSON only inside a managed raw output directory.

Not current-stage behavior:

- no route is created in Phase 8;
- no download is triggered;
- no format is selected;
- no Whisper/transcription action runs.

## `GET /jobs/{job_id}`

Purpose: let the UI poll current job state.

Request shape:

```json
{}
```

Response model:

```json
{
  "job_id": "job-...",
  "task_type": "analyze_url",
  "status": "queued | running | succeeded | failed | cancelled",
  "progress": null,
  "result": null,
  "errors": []
}
```

Errors:

- job not found;
- invalid job ID.

Backend behavior:

- return the current in-memory job state for MVP;
- include result or error summaries when available.

Not current-stage behavior:

- no route is created;
- no persistent database is introduced.

## `POST /jobs/{job_id}/cancel`

Purpose: request cancellation for a running job.

Request shape:

```json
{
  "reason": "user_cancelled"
}
```

Response model:

```json
{
  "job_id": "job-...",
  "status": "cancelled"
}
```

Errors:

- job not found;
- job already finished;
- cancellation unsupported for this task.

Backend behavior:

- mark cancellable jobs as cancelled;
- later terminate child processes for download/transcription jobs;
- keep analysis cancellation best-effort if the subprocess is already finishing.

Not current-stage behavior:

- no route is created;
- no actual process cancellation is implemented in Phase 8.

## `GET /outputs/{job_id}`

Purpose: let the UI show completed local outputs or their managed local path.

Request shape:

```json
{}
```

Response model:

```json
{
  "job_id": "job-...",
  "output_dir": "/managed/local/output/job-...",
  "files": []
}
```

Errors:

- job not found;
- output directory not created;
- job not completed;
- output access blocked by safety policy.

Backend behavior:

- return managed output references only;
- keep paths inside the configured output root;
- avoid exposing arbitrary filesystem browsing.

Not current-stage behavior:

- no route is created;
- no files are generated by Phase 8;
- download/transcription outputs remain out of scope.

## API Safety Defaults

- Backend binds only to `127.0.0.1`.
- CORS is limited to the local frontend origin.
- Analysis is allowed before rights confirmation.
- Download, conversion, extraction, and transcription require `user_confirmed_rights == true`.
- Cookies/login are not implemented in the first MVP.
- Raw `yt-dlp` JSON is not embedded in API responses.
